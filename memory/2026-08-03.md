## Stylesheet fix (the one non-obvious change)

`.cite` carried `white-space: nowrap`, which forced horizontal page scrolling at
380 px for any citation whose label was longer than the viewport — measured
scrollWidth 849 px against clientWidth 380 px, with citation anchors up to
565 px wide. This is a **latent bug affecting every future page**, not something
specific to this topic: real academic titles run to 70+ characters and no
citation label can be kept under ~35.

Fixed while preserving the evident design intent (the `R-NN` code must never
orphan from its title):

```css
.cite { overflow-wrap: break-word; }          /* was: white-space: nowrap */
.cite::after { content: "\00a0" attr(data-code); white-space: nowrap; }
```

The non-breaking space glues the code to the last word, so the title wraps but
the code cannot separate. Verified: 380 px scrollWidth is now exactly 380.

# Follow-up (same day) — inaccessible resources are kept, not cut

## What changed and why

Cutting *A Mind at Play* was the wrong call, and it exposed a bad rule rather
than a bad judgement. `CLAUDE.md` said "Anything you could not verify gets
`tag--unverified` or gets cut. Cut is usually right", which collapses two
unrelated failures:

1. **Cannot confirm the thing exists** — possibly invented. Cutting is correct.
2. **Confirmed it exists, but the URL won't answer a script** — a bot-block, a
   Cloudflare challenge, a temporary outage. Cutting here discards a good
   resource over a transient property of someone else's server.

The new rule, now in both `CLAUDE.md` and `PROMPT.md`: **Inaccessible ≠
unciteable.** Keep the resource, link its canonical home anyway, and state the
problem in brackets at the end of the note. And `tag--unverified` was redefined
to mean *identity not established*, never *server refused me* — using it for the
latter tells the reader something false.
