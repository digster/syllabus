## The decision that mattered: boundaries before prose

Five pages built in one session share a failure mode the single-page sessions
never had — the same subject taught three times, slightly differently, because
each page's author (the same author) reached the point where it was needed.
`CLAUDE.md`'s bloat tests catch this only per page; nothing catches it across
pages.

So the plan fixed an owner for every contested subject before any HTML was
written, and each non-owner cites the owner in one sentence and links it from
`#next`:

| Subject | Owner | What the others do |
|---|---|---|
| MDPs, Bellman, tabular RL, POMDPs | AI-01 | AI-03 assumes it, links back |
| Deep RL — DQN, PPO, MuZero | AI-03 (one module) | AI-01's RL module ends by pointing here |
| RLHF / DPO / GRPO / RLVR | AI-04 | AI-03's deep-RL module names the split |
| Bayes nets, d-separation, HMMs, Kalman | AI-01 | AI-02 owns EM-for-GMMs only |
| GPs, MCMC, variational inference | AI-02 | AI-01 cites for inference machinery |
| VC, Rademacher, PAC | AI-02 | AI-03's theory module starts where it ends |
| Transformer *architecture* | AI-03 | AI-04 assumes it, teaches the *decisions* |
| Tokenization, scaling in practice, serving | AI-04 | AI-03 covers scaling as a research result |
| CLIP, ViT, contrastive learning | AI-03 | AI-05 assumes CLIP at guidance |
| VAE→GAN→diffusion→flow matching | AI-05 | AI-03's architecture module points here |
| Discrete diffusion for text | AI-05 | AI-04 names it as the live alternative |
| Search, SAT/CDCL, planning, CSP | AI-01 | AI-04 contrasts LLM planning against it |

This held. No module on any of the five re-teaches another page's material, and
the five `#next` sections form a connected graph rather than five dead ends.

## Sequencing calls worth remembering

Each of these is a place where the textbook order and the dependency order
disagree, and the dependency order won:

- **AI-01**: SAT *after* CSP — CDCL is a CSP solver that learned to explain its
  failures. And the frame-problem module *before* Bayesian networks, so
  probability arrives as an answer to a problem the reader has already hit.
- **AI-02**: model selection and leakage *before* the model zoo, so every later
  module is evaluated with an instrument the reader already trusts.
- **AI-03**: the generalisation puzzle (random labels, double descent, grokking)
  *before* the architectures, so the reader meets every architecture already
  knowing its performance is not explained by classical theory.
- **AI-04**: evaluation *before* post-training. Every post-training module is an
  optimisation against a metric; a reader who has not seen how badly LLM metrics
  break will read RLHF and RLVR as more reliable than they are.
- **AI-05**: score matching *before* DDPM. Meeting diffusion as a T-step VAE
  makes flow matching look like a different subject; meeting it after score
  matching makes both look like one.

## Research notes

Roughly 130 searches across the five pages. Things that were wrong in memory and
had to be corrected from primary sources:

- A **fabricated Cambridge URL** for Brachman &amp; Levesque (AI-01) — invented
  because a plausible one should exist. It 500'd; the real home is
  `shop.elsevier.com`. This is the anti-pattern `CLAUDE.md` names explicitly and
  it still happened.
- **Two of five remembered YouTube playlist ids** (AI-01) pointed at different
  courses entirely — one to DeepMind×UCL *Deep Learning* rather than the RL
  series, one to MIT 6.041 *Probability*.
- **Two remembered DOIs** (AI-02) were other papers — one an active-learning
  bound, one a handwritten-digits paper. Crossref caught both before use.
- **arXiv title search returned the wrong paper twice** (AI-03): "An Image is
  Worth 16x16 Words" matched a video paper, "The Lottery Ticket Hypothesis"
  matched *Dual* Lottery Ticket Hypothesis. Re-searching on a distinctive
  substring of the subtitle fixed both.
- **An accented character defeated title search** (AI-05): *The Role of ImageNet
  Classes in Fréchet Inception Distance* returns nothing; the id had to be
  confirmed by direct query instead.

Kept-but-unreachable (confirmed by another route, linked anyway, refusal stated

from this environment — identity confirmed via WebFetch, which GitHub does
